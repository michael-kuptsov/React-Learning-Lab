# Работа с Mac и Linux

GitHub хранит общую историю. На каждом компьютере находится отдельная копия репозитория.
Изменения появляются на другом компьютере после commit + push на первом и pull на втором.
Несохранённые в Git файлы и история чата автоматически не переносятся.

## Первый запуск на Linux или другом компьютере

1. Установите Git. Настройте своё имя и email для коммитов.
2. Настройте доступ к своему GitHub по SSH: создайте на этом компьютере отдельный ключ
   через `ssh-keygen -t ed25519`, добавьте публичный ключ (`.pub`) в GitHub → Settings → SSH and GPG keys.
   Закрытый ключ с Mac переносить не нужно. При проверке первого соединения сверяйте отпечаток
   с официальной документацией GitHub.
3. Выполните команду `git clone` из README нужного репозитория.
4. Откройте папку и прочитайте `PROGRESS.md`: там текущая тема и следующий шаг.

Публичный репозиторий можно клонировать и по HTTPS без входа;
для отправки изменений нужен доступ к аккаунту. Инструкция SSH:
https://docs.github.com/en/authentication/connecting-to-github-with-ssh

## Перед началом занятия — в папке нужного репозитория

```bash
git status
git pull --ff-only
```

Перед pull рабочая папка должна быть чистой. Если есть незавершённая работа,
сначала сохраните её отдельным коммитом. Если pull сообщает о расхождении истории,
остановитесь и разберите ситуацию с наставником; не используйте force push.

Прочитайте `PROGRESS.md`. В новом чате попросите наставника сначала прочитать README,
PROGRESS.md и материал текущей темы. Это позволит продолжить занятие на другом компьютере.

## В конце занятия

Обновите `PROGRESS.md`: что сделали, что осталось непонятным, какой следующий шаг.
Затем проверьте и отправьте изменения:

```bash
git status
git diff
git add .
git diff --cached
git commit -m "Кратко описать выполненный шаг"
git push
```

Проверяйте состав коммита. Не добавляйте пароли, токены и личные данные.
Не редактируйте одну и ту же незавершённую работу одновременно на двух компьютерах.
Перед переходом на другой компьютер завершайте push; на другом начинайте с pull.

## Когда появится React-приложение

В README появятся команды установки и запуска. Будем сохранять package-lock.json
и использовать одинаковую версию Node.js на Mac и Linux.
node_modules в Git не хранится: зависимости устанавливаются отдельно на каждом компьютере.
